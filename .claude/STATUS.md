## App (as of current commit)

- Next.js App Router + TypeScript scaffold, routes: `/`, `/tasks`, `/projects`, `/projects/[id]`, `/saves`, `/pages`, `/pages/[id]`, `/share-target`, all deployed and live. Root `/` is now the Today view (DECISIONS.md D-011) — it no longer redirects to `/tasks`; the bottom nav / sidebar's first item is "Today". Nav has 5 items: Today, Tasks, Projects, Saves, Notes (added "Notes" → `/pages`, DECISIONS.md D-012; "Recurring" was added as its own nav item/route by D-018, then folded into a Tasks tab and dropped from nav by D-020 — see below).
- **Auth**: Supabase magic-link email, gating the whole app client-side via `AuthGate` (`src/components/AuthGate.tsx`). No session → email form; link click signs in. Send/resend button has a 60s cooldown (auto-extended if Supabase itself reports a rate limit) to avoid hammering the mail provider.
- **Data**: `src/lib/tasks.ts`, `src/lib/projects.ts`, `src/lib/actions.ts`, `src/lib/saves.ts`, `src/lib/pages.ts`, `src/lib/projectSaves.ts`, `src/lib/checklist.ts`, `src/lib/events.ts` wrap all Supabase reads/writes for their table. App pages/components never call `supabase.from(...)` directly.
- **Tasks**: add (name + optional free-text tag + optional date) via an always-visible input at the top of the list, no modal. Toggle done via checkbox. Each row has a 🚩 flag toggle (`flagged_today`) that surfaces it on the Today view; marking a task done that has a linked action (via `actions.linked_task_id`) prompts `window.confirm()` to also complete that action.
- **Inline accordion expand** (Tasks + Recurring rows, D-020): tapping a row (outside the checkbox/flag/move controls) expands it in place — a sibling `.item-accordion` panel below the row animates open via a CSS `max-height` transition (no JS/library animation), with a tinted/bordered `.item-accordion__body` visually distinct from the row above it. Only one row expands at a time per list (`expandedId` state, tap the open row again or tap another row to switch). Edit/Delete (Tasks) and Edit/Archive (Recurring — Delete pending, tracked below) live only inside the expanded panel now, decluttering the always-visible row to checkbox/name/meta + one quick-action toggle.
- **Recurring Items** (Tasks page's "Recurring" tab, DECISIONS.md D-020, supersedes D-018's placement): `src/components/RecurringItems.tsx` (renamed from `DailyChecklist.tsx` by D-018) is now rendered as a tab on `/tasks` (`src/app/tasks/page.tsx`, `Tasks`/`Recurring` chips) instead of its own `/recurring` route — nav dropped the "Recurring" entry (5 items). Add flow requires an explicit frequency choice — three chips (Daily/Weekly/Monthly, not a dropdown) with a day-of-week picker (weekly) or day-of-month number input (monthly) revealed underneath; Add stays disabled until title + a valid frequency selection are both present. List rows show a checkbox, the title, and inline muted-text progress — a daily item shows its current streak ("N day streak", consecutive completed days walking back from yesterday), a weekly/monthly item shows a completion rate for the current quarter-to-date ("done/due this quarter"). Move carried over unchanged from D-16's build; Edit/Archive moved into a tap-to-expand detail panel (D-020, see Inline accordion expand above) — a hard Delete is planned alongside the existing soft-delete Archive but not yet wired up (tracked in BACKLOG.md). `src/lib/checklist.ts` gained `isDueOn()` (pure due-date check per frequency, clamping `day_of_month` to the last day of short months), `getStreak()`, `getCompletionRate()`, and `listRecurringForToday()` (replaces `listChecklistForToday()`). Schema (`checklist_items.frequency`/`days_of_week`/`day_of_month`) applied manually in the Supabase SQL editor, confirmed by user 2026-08-12; on-device end-to-end verification still tracked in BACKLOG.md Active.
- **Projects / Actions** (DECISIONS.md D-011, schema applied 2026-08-05): Projects list (`/projects`) is a card grid — title, status badge (active/on_hold/done/archived or "unset"), priority badge (high/medium/low or "unset"), tags, live recursive progress % rolled up through child projects, due date. Quick-capture is name-only (status/priority start null). Project detail (`/projects/[id]`) has inline-editable name/status/priority/due date/tags/description (each field saves on blur/change, optimistic with rollback on error), a progress bar, a sub-projects grid (`parent_id`, `on delete restrict`), and an actions list below: quick-add via Enter, checkbox to complete, sort (created/title/completed) and filter (all/open/completed) controls, a 🚩 flag toggle, and a "Convert to task" button per row that inserts into `tasks` and soft-links via `linked_task_id` (action stays visible, shows "🔗 linked to task" once converted, no copy-and-delete). Setting status to `done` with open actions shows a soft inline warning ("N actions still open") rather than blocking. A "Delete project" button at the bottom of the detail page (2026-08-08) pre-checks for sub-projects client-side (`projects.parent_id` is `on delete restrict`) and blocks with a clear message rather than letting the raw FK error surface; confirmed via `window.confirm()` per D-010.
- **Today view** (`/`, DECISIONS.md D-011): unified list of `flagged_today` tasks (flat) and `flagged_today` actions (grouped by project, project name links to its detail page). Completing an item from here clears its `flagged_today` flag and removes it from the list. Below that, an "Upcoming" section (DECISIONS.md D-013, 2026-08-08) merges and sorts by date anything with a future due date across tasks/actions/projects, excluding anything already flagged or done/completed so nothing duplicates with the section above. Fed by a new `actions.due_date` column (previously actions had no date field).
- **Calendar Phase 1** (Today page's new "Calendar" tab, DECISIONS.md D-019): not a new route — there is no Dashboard route in this app (it's still an unbuilt Horizon item), so Calendar was added as a second tab on the existing Today page (`src/app/page.tsx`) alongside the original "Today" content; tab selection is local state, resets on reload. `src/components/CalendarTab.tsx` renders a Monday-first 6-week Month grid (current day highlighted, event dots + due-task counts per day) or an Agenda list (grouped by day, empty days skipped) over one shared visible-month range with Prev/Today/Next controls; the Month/Agenda toggle and the Today/Calendar tab both reuse D-018's `.chip` pattern. Tapping a day opens `src/components/DayDetailPanel.tsx` via the existing `BreadcrumbMenu` component (desktop dropdown / mobile bottom sheet — already used by Project detail and the Pages editor breadcrumb), showing that day's events (with delete) and due tasks (read-only, linking to `/tasks` since no per-task detail page exists) plus a quick-add event form (title, all-day toggle, date/time, optional end time/location/description). New `src/lib/events.ts` (list/create/update/delete against a new `events` table) and a `listTasksInRange()` addition to `src/lib/tasks.ts` feed both views. Schema (`events` table) applied manually in the Supabase SQL editor, confirmed by user 2026-08-12; on-device end-to-end verification still tracked in BACKLOG.md Active. Deferred: `.ics` import, share-target extension, Google Calendar sync, recurrence, drag-to-reschedule, event-to-project linking (BACKLOG.md Horizon).
- **Projects: outcome, notes, saves** (DECISIONS.md D-012, schema applied 2026-08-05): project detail gains an inline-editable `outcome` field (free text, save-on-blur, same pattern as `description`) — also shown on the card grid ("No outcome set yet" when null). An "Add notes" affordance creates a `pages` row, sets `projects.page_id`, and navigates into the Pages editor; once set it shows as a link into that page instead. An "Attached saves" section lists saves linked at the project level (`project_saves.action_id` null) with an attach-a-save picker; each action row has a ▸/▾ expand toggle revealing a same-pattern attached-saves section scoped to that action (`action_id` set). Both attach flows and Save Manager's new "Link to project" action (project picker → optional action picker) write to the same `project_saves` join table via `src/lib/projectSaves.ts`.
- **Pages / Notes** (`/pages`, `/pages/[id]`, DECISIONS.md D-012): built from scratch this round — designed pre-rebuild but never carried over until now. Full block-based editor: `src/components/pages/PagesShell.tsx` (hierarchy nav — desktop persistent sidebar ≥768px, recursive tree over a flat `listPages()` fetch; below 768px the tree is injected into the app-wide shared mobile drawer via `usePageDrawerContent`, see Layout below, 2026-08-08), `src/components/pages/PageEditor.tsx` (title/emoji inline-editable, blocks array; Enter creates a new block and focuses it, Shift+Enter soft-breaks within a text block, Backspace at the start of an empty block deletes it and refocuses the neighbor — added 2026-08-08, previously the editor had no keydown handling at all), `src/components/pages/BlockMenu.tsx` (shared block-type menu — identical markup, CSS alone switches it between an inline dropdown at ≥768px and a bottom sheet at <768px). Writes debounce 800ms after the last edit via a single combined save (title+emoji+content together, tracked in refs to avoid stale-closure bugs); a `flush()` is awaited before any sub-page creation writes to the parent's content, so a fast sub-page creation right after typing can't silently drop the pending parent edit. Deleting a page with children is blocked with a clear message (`src/lib/pages.ts`'s `deletePage()` pre-checks child count, also catches the FK-restrict error code as a fallback) rather than failing silently.
  - **Design assumptions made** (not specified in the original ask, chosen to keep a first working version shippable — flagged per the task's own guidance to make a reasonable call and note it rather than stall):
    - Block type list: `text`, `heading`, `checklist`, `bullet`, `page_link` — the four named as examples in the ask, plus `page_link` (needed to satisfy the explicit "createSubPage() writes to the parent's content" requirement: creating a sub-page inserts a `page_link` block referencing the new page, it doesn't just set `parent_id`).
    - Slash-command trigger: any block whose text starts with `/` opens the block-type menu (no filtering by what follows the `/`); selecting an option converts that block in place if it was empty, or is inserted as a new block after when triggered via the explicit "+" button per block row instead.
    - Sub-page creation is scoped to the in-editor "Sub-page" menu option only (creates the child row, inserts the `page_link` block, flushes+saves, navigates). The sidebar has a separate "+ New page" button for root-level pages (no content mutation needed there). There's no "add child page" affordance directly on the sidebar tree itself yet — only via a parent page's own editor.
    - No rich-text formatting (bold/italic/links-within-text) — each block is a single plain-text field. No drag-to-reorder blocks yet — order is create-order only, blocks can be deleted and re-added but not dragged.
    - "Attach a save" pickers (project/action-level, and Save Manager's project/action pickers) show *all* saves/projects/actions without filtering out already-linked ones — duplicate `project_saves` rows are technically possible if the same save is attached twice; not deduplicated this round.
- **Saves** (DECISIONS.md D-003, deliberate capture-first exception): add (url + optional title + platform select defaulting to auto-detect) via the same top-of-list pattern; list links out to each saved URL. `saves` table pre-existed in the repurposed NOTED Supabase project — columns were confirmed live rather than assumed; see SCHEMA.md. `cleanUrl()` strips `utm_*`/`rcm` tracking params before insert; `detectPlatform()` maps the URL host to one of YouTube / Articles / LinkedIn / Facebook / Reddit / Websites (defaults to Websites). If the title is missing **or is itself a URL** (Android share sheets often pass the URL as the title), `src/lib/linkPreview.ts`'s `fetchPageTitle()` fetches the page server-side and extracts `og:title`/`<title>` before falling back to the raw URL, skipping junk titles like login walls and bot challenges (DECISIONS.md D-015 + Updates, 2026-08-08) — best-effort, not guaranteed. Existing rows with URL-shaped titles are backfilled automatically once per `/saves` visit (failed rows keep the URL and retry next visit); a progress button shows during the run. **Reddit is the exception throughout**: no automated fetch can reach a Reddit title (WAF blocks servers/proxies, no CORS for browsers — D-015 Updates 4–7), so Reddit URLs skip the server fetch and are excluded from the backfill; their titles come from the share page's prompt instead. Dormant OAuth support (`REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET` env vars) exists in `linkPreview.ts` should Reddit's app policy revert.
- **Share target**: `/share-target` receives Android's share sheet via the PWA `share_target` manifest entry (GET, `title`/`text`/`url` params), extracts the first `http(s)` URL from `text` when `url` is empty, POSTs it to the `/api/share-target` route handler, then redirects to `/saves` after ~1.2s — unless the save came back with a URL-shaped title (no title was fetchable, e.g. any Reddit link), in which case the page first shows an optional title input (Save title / Skip) that updates the row via `PATCH /api/share-target` (D-015 Update 7). The route handler (`src/app/api/share-target/route.ts`) writes to `saves` via a `service_role` client built inline, stamping `user_id` from the `NOTED_USER_ID` env var — not the browser session (DECISIONS.md D-009; see MISTAKES.md for why this changed); the PATCH scopes updates to the same `user_id`. Requires `SUPABASE_SERVICE_ROLE_KEY` and `NOTED_USER_ID` set in Railway and `.env.local`.
- **Add buttons** (Tasks + Projects): guarded against double-submit via an `isAdding` loading state — button disables and reads "Adding…" while the insert is in flight, handler re-entry guarded too. Fixed after a duplicate-row bug; see MISTAKES.md. Saves' add form follows the same pattern.
- **Layout**: bottom nav below 600px, sidebar (with sign-out) at/above 600px. A mobile hamburger + shared drawer (`src/components/NavShell.tsx` + `src/components/DrawerContext.tsx`, added 2026-08-08) also lives below 600px on every route — empty by default ("Nothing here yet."), except `/pages`/`/pages/[id]` which injects its page tree via `usePageDrawerContent`. This replaced a Notes-only hamburger drawer that switched at a 768px breakpoint (vs. the sidebar's 600px), which could show both simultaneously between 600–767px. The drawer's content-injection initially shipped with an infinite-render-loop bug that froze the entire Notes route (fixed same day, 2026-08-08 — provider callbacks and injected content are now memoized; see MISTAKES.md's top entry for the harness-confirmed post-mortem). The root viewport briefly set `interactiveWidget: 'resizes-content'` (2026-08-08) to fix the block-editor's slash-command menu rendering behind the on-screen keyboard; reverted the same day. The broken-bottom-nav report initially blamed on it was later root-caused to unbreakable-URL overflow on Saves expanding the mobile layout viewport (confirmed via repro, fixed with `overflow-wrap: anywhere` on `.item__name` + `overflow-x: clip` on `.main` — see MISTAKES.md's top entry). The slash-menu-behind-keyboard problem remains unfixed pending a scoped `visualViewport` approach (BACKLOG.md). Hand-rolled CSS, no UI library, auto light/dark via `prefers-color-scheme`.
- **PWA**: `public/manifest.json` + `public/sw.js` (app-shell caching only, no offline write queue). `sw.js` serves the navigable HTML document network-first with a cache fallback for offline use, and the static shell assets (manifest, icons) cache-first — see MISTAKES.md for the stale-shell bug this replaced. Web Share Target wired (`share_target` in the manifest → `/share-target`). Installable to an Android home screen; icons are placeholders — `public/icon.svg` plus generated `public/icon-192.png` / `public/icon-512.png` (same blue rounded-square "OS" mark, added so `share_target`/maskable-icon requirements are met) — swap all three for real artwork before shipping.
- Not implemented: everything not listed above. See BACKLOG.md.
